# Tab Migration Playbook

Use this playbook when migrating any `ui/tab_*.py` to the shared design
system. The canonical reference implementation is
[`ui/tab_rate_analytics.py`](../ui/tab_rate_analytics.py) — it's small
(~230 LOC) and already in production, so you can grep it for any pattern
you need (`page_header`, `metric_card_row`, `wsj_market_table`, `badge`).

Before starting a tab, look up its row in
[`audit-baseline.csv`](audit-baseline.csv) (generated by
`python tools/styles_audit.py`). The `roi_score` column tells you how much
duplication the refactor will remove; attack the top of the list first.

## The 10-step recipe

Work through these in order for each tab. Each step has a verification
check you can run without opening the app.

### 1. Delete palette redeclarations
Every `C_BG = "..."`, `C_SURFACE = "..."`, `C_CARD = "..."`, `C_HIGH`,
`C_MOD`, `C_LOW`, `C_ACCENT`, `C_CONV`, `C_MACRO`, `C_TEXT`, `C_TEXT2`,
`C_TEXT3`, `C_RULE`, `C_BORDER` assignment at module level is dead weight.
Import from `ui.styles` instead:

```python
from ui.styles import C_ACCENT, C_HIGH, C_LOW, C_MOD, C_TEXT, C_TEXT2
```

**Check:** `grep -E '^C_[A-Z_]+ *=' ui/tab_foo.py` returns nothing.

### 2. Page header → `page_header(...)`
Replace any ad-hoc `<div style="...">` title block at the top of `render()`.

```python
from ui.styles import page_header

page_header(
    title="Freight Rate Analytics",
    subtitle="Rate regime detection, percentile ranking, and market spread analysis",
    badge_text="LIVE",
    badge_color=C_HIGH,
)
```

### 3. KPI row → `metric_card_row(...)`
Replace hand-built `st.columns(4)` + inline HTML cards:

```python
from ui.styles import metric_card_row, C_ACCENT, C_HIGH, C_MOD

metric_card_row(
    [
        {"label": "Market Regime", "value": market_regime,
         "accent": _market_regime_color(market_regime)},
        {"label": "Avg Z-Score",   "value": f"{avg_z:.2f}",  "accent": C_ACCENT},
        {"label": "Avg Percentile","value": f"{pct:.0f}th",  "accent": C_ACCENT},
        {"label": "Avg Volatility","value": f"{vol:.1f}%",   "accent": C_MOD},
    ],
    columns=4,
)
```

### 4. Tables → `wsj_market_table(...)` with `_mono` / `_sans` cell helpers
Build cells with tab-local helpers that only style *content*:

```python
from ui.styles import wsj_market_table, C_TEXT, C_TEXT2

def _mono(v: str, color: str = C_TEXT) -> str:
    return f'<span style="font-family:var(--mono);color:{color};font-variant-numeric:tabular-nums;">{v}</span>'

def _sans(v: str, color: str = C_TEXT2, weight: int = 400) -> str:
    return f'<span style="font-family:var(--sans);color:{color};font-weight:{weight};">{v}</span>'

rows = [
    [_sans("Transpac EB", color=C_TEXT, weight=700),
     _mono(f"{rate:,.0f}"),
     _mono(f"{z:+.2f}", color=_zscore_color(z)),
     badge(regime_label, color=_regime_color(regime_label))],
    # ...
]
wsj_market_table(["Route", "Rate", "Z-Score", "Regime"], rows)
```

### 5. Insight tiles → `insight_card_html(...)`
`st.markdown(insight_card_html(title=..., score=..., action=..., rationale=..., category=...), unsafe_allow_html=True)`

### 6. Status chips → `badge(...)` / `status_badge(...)` / `regime_pill(...)`
Use `regime_pill(regime, mapping=...)` when the mapping is domain-specific
(see how `tab_rate_analytics.py` calls `_regime_color`).

### 7. Section dividers → `section_header(...)` / `wsj_section(...)`
Drop inline `<h3>`s and manual rule divs. `section_header` adds the heavy
top rule that matches WSJ visual language.

### 8. Sub-section headers → CSS class, not inline HTML
```python
st.markdown('<div class="sub-section-header">Route-Level Detail</div>',
            unsafe_allow_html=True)
```

### 9. Chart styling → `dark_layout()` / `apply_dark_layout(fig)`
Never hand-set `paper_bgcolor`, `plot_bgcolor`, or font colors inside a tab.

```python
from ui.styles import apply_dark_layout

fig = go.Figure(...)
apply_dark_layout(fig, title="", height=360, showlegend=True)
```

### 10. Every figure/table gets a provenance pill
Every chart, table, or KPI block should show where its data came from.

```python
from ui.styles import live_data_badge, source_footer
from data.quality import DataSource

baltic = DataSource.scraped("Baltic Exchange", url="https://www.balticexchange.com")
st.markdown(live_data_badge(baltic), unsafe_allow_html=True)

# or, at the bottom of a composite section:
st.markdown(source_footer([baltic, fred_source]), unsafe_allow_html=True)
```

When a series is synthetic, use `DataSource.demo("...")` — the pill goes red
and the user immediately knows not to trust the number.

## Common pitfalls

* **Don't bring over `box-shadow: 0 0 20px ...` glows.** The WSJ aesthetic
  is flat. Drop them.
* **Don't introduce new palette constants.** If you need a new semantic
  color, add it to `ui/styles.py` once and import it everywhere.
* **Keep domain→color maps local to the tab.** A regime→color or
  signal→color lookup is domain-specific; keep it in the tab file and feed
  it to `badge`/`regime_pill` as an override.
* **Never silently fall back to mock data.** If the feed fails, wrap the
  fallback in a `DataSource.demo(...)` or `DataSource.modeled(...)` so the
  pill tells the truth.

## Verification checklist per tab

- [ ] `grep -E '^C_[A-Z_]+\s*=' ui/tab_foo.py` → no matches
- [ ] `grep -E 'from ui\.styles import' ui/tab_foo.py` → at least one match
- [ ] `python tools/styles_audit.py --print` shows `imports_styles=1`
      and palette_redecls = 0 for this tab
- [ ] Smoke test still passes (`pytest tests/`)
- [ ] Manual check: open the tab; spacing, fonts, and rule lines match
      `tab_rate_analytics`

## Effort estimates

| Tab size                    | Expected effort |
|-----------------------------|-----------------|
| Small (≤500 LOC)            | ~1 hr           |
| Medium (500–800 LOC)        | ~2–3 hrs        |
| Large (>800 LOC)            | ~4–6 hrs        |

Run the audit *before* and *after* migrating a tab; the total
`palette_redecls` and `inline_divs` reported at the bottom of the audit
output are your delta.
